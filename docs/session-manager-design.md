# 微信 Codex 任务总管

使用者是已配对并获准访问本机会话的个人。可以管理本机所有未归档的可见会话，也可以配置较窄的项目范围。微信里以自然语言查找、选择、继续和总结 Codex 会话，斜杠命令提供同样的入口。

## 使用流程

| 用户故事 | 交互与验收 |
| --- | --- |
| 我想按项目或任务名称找回已有会话 | “切到 code_bot 里修审批的会话”匹配可管理会话的项目和标题。唯一匹配时选中，多条时返回编号。用户回复“第一条”后显示实际选中的会话。找不到目标时保留原选择。 |
| 我想从微信接着原会话工作 | “继续修，先跑审批测试”由总管生成任务单，路由到原 ID。共享服务持有时直接提交，确认由桌面端持有时进入原会话队列，归属不明时询问是否移交。 |
| 我想在手机上看任务怎么做的 | “总结一下这轮怎么做的，重点说还有哪些没做完”读取阶段更新和验证记录，按顺序汇报步骤、结果和待办。运行中的总结注明“截至目前”。 |
| 我想把独立的工作放到新会话 | 先核对有无合适的原会话。项目明确、任务可独立开展时可以新建，拿不准时询问。新会话写入第一轮后，可在 Codex App 中查看。 |
| 我想同时盯住几个正在跑的任务 | “帮我盯着 atoms-demo 和 Cocos 台球”分别监听各项目的当前任务轮次。关键进展和结束状态通过微信通知，可随时查看或停止监听。 |
| 我想在一个任务卡住时继续别的工作 | A 无进展时仍能查询桥接状态、切到 B 并提交任务。A 的活动状态以当前 App Server 可见状态为准。整个 App Server 不可用时，微信入口仍响应并报告故障。 |

## 职责和状态

- 微信长轮询独立于 Codex。每批入站消息与微信游标在一个本地 SQLite 事务中提交，以微信账号和消息标识去重。按发送者保留路由命令的顺序，帮助和桥接状态走独立入口。
- 现有 App Server 继续执行项目任务。请求有超时，连接断开时结束等待并单独重连。正在运行的会话拒绝叠加普通指令。已选目标失效时提示重新选择。
- 启用总管后，普通消息先交给独立模型规划。程序校验动作、目标和权限，再读取历史、查证已有测试记录，或按目标 ID 发送整理后的任务单。任务单包含目标、范围、用户约束和回报要求，当前选中的会话保留。目标不唯一时等待用户选择；原会话由另一个本机进程持有时，任务单交给该会话的 Codex 队列。帮助、健康状态和明确的协议操作可直接处理。
- 总管模型默认复用本机 Codex 登录，每个微信对话使用一条独立、持续的只读总管会话。总管持有目标、约束和派活决策，项目会话负责检查和执行。后台总结读取有限的过程证据，独立于总管对话运行。
- 监听和派活回报保存在 SQLite，由独立后台任务跟踪准确的会话 ID 和轮次。中途提醒节流，结束回报去重。独立桌面进程的任务以实际写入的过程和结束记录为准。
- 回复先写入发件箱，复用同一个微信客户端消息 ID 重试。重启后继续处理未领取入站和待发回复。提交结果不明的任务保留为待确认，不自动重发给 Codex。
- 本机用 launchd 托管桥接进程。运行中追加指令、停止以及跨 App Server 实时控制属于后续阶段。

## 验收

1. 两个项目的原生空闲会话分别收到唯一测试指令，按原 ID 读取历史验证。
2. A 的任务保持运行或 RPC 超时，微信状态仍可查，B 能收到自己的任务。
3. 模型总结超时，微信可以继续查询和切换。
4. 模拟桥接退出。入站游标和待发回复恢复，已领取但结果未知的任务不会重新提交。
5. 在微信新建会话，通过同一 ID 在 Codex App 找到它。
6. 同时监听两个项目，确认进展、结束回报和重新启动后的恢复。验证工具记录掩盖阶段汇报时，仍可按轮次翻页读取过程。
